# upperadd v0.1.0 — decided spec

Everything here was decided with the owner (2026-09-25 grilling session).
Anything marked OPEN is deliberately left for implementation discussion.
Companion docs: [../AGENTS.md](../AGENTS.md) (conventions, dep block,
fork rules), [../PROMPT.md](../PROMPT.md) (kickoff).

## Product

A persistent Wayland overlay — one shortcut away — to jump into your
markdown notes: fuzzy-search `/m`, live-preview the highlighted note,
one keypress into a real editor. State survives toggling (search text,
selection, scroll stay put while you work elsewhere).

## Architecture

```
upperadd.service (systemd --user, enabled, auto-start)
  └─ upperadd daemon  ── owns ── layer-shell Top overlay (exclusive kbd while shown)
                    └─ owns ── mdrv-db slug "upperadd" (/x/db/upperadd, single writer)
                    └─ watches /m (notify) → incremental reindex
ua (same binary, CLI mode) → $XDG_RUNTIME_DIR/upperadd.sock
  verbs: toggle (default) | show | stop | status | reindex
```

- Layer-shell **Top** layer (never Overlay — z-order gotcha), cursor's
  output, `keyboard_interactivity = exclusive` while shown.
- Surface fully transparent; the app paints its own rounded translucent
  panels.

## Layout

fzf-style split:

- **left ~25%**: search input (top) + result list (rest)
- **right ~75%**: live markdown preview of the highlighted note

Both panels translucent with **different** background opacities
(configurable). Esc = hide overlay (daemon keeps running, state kept).
Toggle again = reappear where you left it.

## Data model

- `/m` markdown files = the ONLY content source of truth.
- mdrv-db (engine crate `mdrv-db = "0.5"`) holds metadata + search index;
  fully rebuildable via `ua reindex` (files → DB, from scratch).
- **Section-level indexing** — a file may contain multiple notes:
  - split on H1 headings (`^#\s`) by default
  - leading frontmatter (`---`…`---` first thing in file) = metadata,
    never a separator
  - `[sections] separator = "h1" | "hr"` config flag; `"hr"` (a lone
    `---` line) is opt-in because `---` collides with thematic breaks
  - index unit = (file path, section start line, heading/title)
  - results anchor to the section: preview scrolls to it; editor opens
    at its line

## Search & ranking

Live as-you-type, over the DB index: fuzzy on title/path first, then
content substring, mtime as tiebreak (newest first). Must feel instant
at personal-collection scale (≤10k notes).

## Preview rendering

pulldown-cmark with GFM extensions (tables, strikethrough, tasklists) →
styled gpui divs; syntect code highlighting; images via `img()` with
relative paths resolved against the note's directory.

## Editor handoff (Enter)

- Configurable command template, default `neovide`:
  `[editor] command = "neovide"`, args template with `{file}` / `{line}`
  placeholders (e.g. `+{line} {file}`).
- On Enter: spawn editor detached → **hide the overlay** (exclusive
  keyboard must release so the editor receives keys) → fs-watch picks up
  the save → next toggle shows fresh content. No manual reindex.

## Config

`~/.config/upperadd/config.toml` (breaking vs v0.0.2's YAML — no
migration):

```toml
[notes]
dir = "/m"

[window]
panel_alpha = 0.92 # left panel
preview_alpha = 0.80 # right panel
corner_radius = 16.0
width_fraction = 0.7 # of cursor output
height_fraction = 0.7

[sections]
separator = "h1" # "hr" = split on lone --- lines too

[editor]
command = "neovide"
args = ["+{line}", "{file}"]
```

## Hyprland integration (documented in README)

```
bind = $mainMod, N, exec, ua toggle
layerrule blur, upperadd
```

Blur is compositor-side; app only ships the transparency.

## mdrv-db integration

- Rust engine crate direct dep (crates.io `mdrv-db = "0.5"`; local-dev
  override: path `/g/mdrv-db/crates/mdrv-db`).
- Fleet: slug `upperadd`, data `/x/db/upperadd`, engine name `upperadd`;
  register in `~/.config/mdrv-db/config.toml` (apps never read it).
- Daemon = single writer (fjall file lock). Schema OPEN (see below);
  requirements: notes table keyed by (path, section line) storing
  title/heading/mtime/hash; content searchable; index disposable.

## Out of scope (v0.1.0)

In-app editing (opt-in later), Windows, wikilinks/footnotes, tags UI,
themes, sync, any v0.0.2 carryover (memos, completions, SurrealDB).

3. Visual tuning: exact alphas/radius, focus rings, blur interplay.
4. Output tracking: follow cursor per-toggle vs pinned to launch output.

## Resolved OPEN items (2026-09-25, second grilling round)

1. **mdrv-db schema**: app-facing storage is SQL-only; owner approved mdrv-db
   0.5.1 exporting the Turso `DataPort` behind an optional `turso` feature
   (published via the repo's tag-triggered release workflow — never local
   `cargo publish`). upperadd depends on `mdrv-db = { version = "0.5.1",
   features = ["turso"] }`; no rusqlite anywhere. One table
   `sections(path, line, title, section_mtime, hash, content)`, PK
   (path, line), created via `engine.bootstrap`; `ua reindex` = DROP+CREATE
   - re-walk `/m`, executed by the daemon over the socket (it is the single
     writer).
2. **Search**: section metadata (path/line/title/mtime) cached in daemon
   memory — title/path fuzzy in RAM; content substring = SQL LIKE,
   debounced ~30ms; trigram table only if profiling shows >50ms lookups.
   Results render through `uniform_list` from day one (virtualization OPEN
   closed: the primitive exists in the fork).
3. **Hide/show**: `Window::set_visible` (unmap/remap) — owner picked early
   testing. Fallback if exclusive keyboard does not survive remap or the
   executor misbehaves: persistent surface + empty render + empty input
   region + keyboard None (gpui-ce doc §16.2). Findings land in `docs/`.
4. **Output**: gpui exposes no runtime output move (grep-verified), so v0.1
   pins one persistent window to the output resolved at daemon start
   (`[window] output = "cursor" | "primary" | <index>`); lazy per-output
   windows are the v0.2 upgrade path.
5. **Geometry** (OPEN 3 values still deferred to M4): full-output
   transparent layer surface (all four anchors, exclusive_zone -1, 0×0
   bounds), panel as an inner div docked via 9-way `[window] anchor`
   (default `bottom-left`), `margin = 16.0`, width/height fractions
   unchanged.
6. **Section metadata**: none stored in the markdown files (per-section
   .ini blocks rejected as unscalable). Per-section mtime is derived by
   hash-diff against existing DB rows; cold rebuilds fall back to file
   mtime.
7. **`hr` separator**: file-leading `---`…`---` is frontmatter and inert in
   v0.1 (skipped, no keys parsed); in `hr` mode `---` splits only when
   blank-line-delimited; `---` after a text line is a setext H2, never a
   separator; `***`/`___` never split.
8. **Sections & search details**: content before the first H1 is its own
   section titled by filename stem; empty query lists all sections by
   section_mtime desc.
9. **CLI/lifecycle**: single bin `upperadd` (clap derive), `ua` = documented
   symlink; no auto-spawn (friendly error instead); stale socket
   probe+unlink on bind; `ua stop` = graceful daemon exit; engine opened at
   daemon boot (holds the fjall lock); view state is in-memory only.
10. **gpui-ce consumption**: git-tag form per `/g/gpui-ce/MDRV.md`
    §Registry (`mdrv-gpui-0.0.260925`); path form only for local fork dev.
